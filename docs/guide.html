Field guide

CSV-o-Matic

A read-only MCP server that lets a model investigate one security at a time across very large ETL CSV files. It reports what is in the files you point it at. Choosing the files and drawing conclusions stays with the model.

  • 9 tools
  • read-only
  • no database, no index
  • built for multi-gigabyte files

The idea in one minute

An ETL process moves data through a chain of folders. Each step reads CSV files from one folder and writes new ones to the next. When a security goes missing or a value looks wrong, the answer is in those files: the last file that has it, the first that does not, and the rule in between.

The files can be several gigabytes each, so a model cannot read them. CSV-o-Matic gives it nine tools that answer narrow questions about them. The division of labour is strict.

  • The model decides which process, folder and file to look at, follows the chain upstream and downstream, and explains what it finds.
  • The server reads the file it is asked about, from disk, at that moment, and reports exactly what is there. It keeps no copy and no index, and it never writes.

Everything is organised in four layers. Each tool works at one of them.

ProcessA named ETL flow with steps, described in a maintained process map.
FolderWhere one step leaves its output. Only folders named in a process map can be read.
FileOne CSV per run. Its name carries a business date and a run timestamp.
RowOne record for a security. Matched by exact text, returned with its column labels.

Every search gives one of three answers

This is the most important idea on the page. “Not found” can mean two different things: the value is not in the file, or the server could not finish looking. CSV-o-Matic never lets those blur. Each search result carries an outcome.

match_found

At least one row holds the value exactly.

A match does not mean you have every match. Check results_are_partial.

confirmed_absent

The whole file was read and no row holds the value exactly.

Only given after a complete, trustworthy scan. This is evidence you can state.

inconclusive

No match was seen, but absence is not proven.

The scan was cut short, or the file could not be read reliably. Never report this as absent.

Alongside the outcome, each result has a scan block saying how far the scan got and why it stopped, and an explanation in plain words. Use the panel below to see how they combine.

Level 1

Find your way: process, folders, files

Before searching anything, the model needs to know how the process works and which file to open. Three tools cover that. None of them reads a CSV's contents.

Tool 1 of 9

get_process_map

Describes an ETL process: its steps, folders, how files are named, which columns identify a security, and the rules that change or drop rows.

Use it when

Starting any investigation, and again whenever you need the rule that explains a difference between two folders.

Where the answer comes from

Maintained YAML files, one per process. They are re-read on every call, so an edit is live at once.

Parameters

NameMeaning
processoptionalProcess id or name. Leave it out to list the processes that exist.
step_idoptionalReturn one step in full, with the folders it touches. Useful when a whole map is too large for one response.
  • Branches show up as a step with several downstream steps, each with a branch_condition.
  • run_semantics says how retries, reruns and backfills appear in the files. Read it before comparing two files for the same date.
  • field_mappings give the column name on each side of a step, which you need when a column is renamed.
  • A map with a mistake in it is left out and reported under process_map_load_errors.

Tool 2 of 9

list_folders

Lists the folders the process maps describe, with what each holds and which steps read or write it.

Use it when

Deciding where to look. The folder value of an entry is what every other tool expects.

Worth knowing

This is the allow-list. A folder that is not in a process map cannot be read by any tool.

Parameters

NameMeaning
processoptionalOnly this process's folders. Leave it out for every folder.
offsetoptionalContinue a listing that was cut short, using its next_offset.
  • A folder shared by two processes appears once, with both under used_by.
  • exists_on_disk tells you at once if a mapped folder is missing.
  • identifier_columns names the column to search and what kind of identifier it holds.

Tool 3 of 9

list_csv_files

Lists the CSV files that exist in one folder right now, with size, modification time, and the dates read from each filename.

Use it when

Choosing which run to open. Several files for one business date is a finding in itself.

Two kinds of time

filename_tokens hold the business date and run timestamp. filesystem_modified_time is only when the file landed on this disk.

Parameters

filename_containsoptionalKeep filenames containing this text. Case does not matter.
date_from, date_tooptionalInclusive date range, YYYY-MM-DD.
date_fieldoptionalWhich date the range applies to: a filename token such as business_date or run_timestamp, or filesystem_modified. Defaults to the folder's main filename date.
descendingoptionalSort filenames descending (the default) or ascending.
offsetoptionalContinue a truncated listing.

Reading a folder: runs, reruns and backfills

The whole normalised folder, as list_csv_files returned it, with each file classified from its filename tokens alone. Note that every file has the same modification time, because the share was copied overnight. That is why modification time is never used as a business date.

FileBusiness dateRun startedModified on diskHow to read it
  • Only regular .csv files directly in the folder are listed. Links, subfolders and other files are counted under other_entries_ignored.
  • A file whose name does not fit the folder's convention is still listed, with matches_filename_convention: false.
  • Filtering on a filename date leaves out files with no readable date, and says how many.

Level 2

Look at a file before searching it

A search needs an exact column name. These two tools give you the layout of a file without reading its data.

Tool 4 of 9

inspect_csv_headers

Returns a file's column names in their original order. On request it adds a few leading rows so you can see what the values look like.

Use it when

You are about to search a file you have not seen, or a search failed with column_not_found.

Do not use it for

Deciding whether a security is present. The sample is only the top of the file.

Parameters

NameMeaning
folder, filenamerequiredThe file, named exactly as list_csv_files returned it.
sample_rowsoptionalHow many leading data rows to include. Default 0. The server caps it at 10 by default.
sample_columnsoptionalLimit the sample to these columns.
column_offsetoptionalContinue a column list that was cut short.
  • If a name appears twice in the header, rows label the columns name [col N], and you select one as #N.
  • A header that reads as one column full of semicolons, tabs or pipes gets a warning that the folder's delimiter is probably wrong.

Tool 5 of 9

search_column_names

Finds the columns whose names contain a term, and tells you where they sit.

Use it when

The file has hundreds of columns and you want the price or identifier ones without pulling the whole header.

How it matches

Part of the name is enough and case is ignored. This is the one place matching is loose, because it is about names, not data.

Parameters

NameMeaning
folder, filenamerequiredThe file.
termrequiredText to look for inside column names.
  • When nothing matches, similar_column_names offers the closest names.

Level 3

Search for a value

Three tools read the data. They share one matching rule, so learn the rule first.

The matching rule: exact text, whole field

A row matches when the field equals the search value character for character. Nothing is converted. So 0417382 and 417382 are different values, Halvorsen does not match Halvorsen Aerospace PLC, and a trailing space makes a different value. Any exact value can be searched for, not only security identifiers. A portfolio code works just as well.

Strictness would be unhelpful on its own, so the server also reports near misses: values that are not matches but explain why there was none. Try it.

    Tool 6 of 9

    find_security_in_file

    Returns the rows of one file whose chosen column equals the value exactly, with their original column labels.

    Use it when

    You know which column holds the identifier. This is the main evidence tool.

    It returns

    The whole row, or just the columns you ask for. Values are text exactly as in the file.

    Parameters

    NameMeaning
    folder, filenamerequiredThe file to search.
    identifierrequiredThe value to match, as text. Up to 200 characters.
    identifier_columnrequiredExact column name, or #N for the Nth column.
    columnsoptionalReturn only these columns. Leave out for the whole row.
    max_rowsoptionalRows in this response. The server caps it at 25 by default.
    cursoroptionalA next_cursor from an earlier response of this same search. See Level 4.
    max_scan_secondsoptionalA shorter time budget for this call. See Level 4.
    • record_number counts from 1 with the header as record 1, so it equals the spreadsheet row number unless a field contains a line break.
    • records_after_header in the scan block is how many records the file has. A file with a header and nothing else shows 0, which is often the real answer.
    • A row with more or fewer fields than the header is still returned, with a field_count_mismatch note.
    • Very long cell values are cut and listed under truncated_cells.

    What near_misses reports

    Near misses are never counted or returned as matches. They cost nothing extra, because only records containing the search text are ever examined. There are four kinds.

    FieldMeaningTypical cause
    identifier_inside_a_longer_valueThe text sits inside a longer value in the searched column.A lost leading zero, a partial name, a prefix or suffix added by a step.
    same_value_with_surrounding_whitespaceEqual once spaces are trimmed.Padded fixed-width exports.
    exact_value_in_other_columnsThe exact value is in the row, in a different column.You searched the wrong column.
    inside_a_multi_line_value_in_another_columnThe text is inside a value that spans lines.An unclosed quote has swallowed whole rows.

    Tool 7 of 9

    search_across_columns

    Returns the rows where any column equals the value exactly, and names every column that matched.

    Use it when

    You do not know which column holds the identifier, or you want to know where else a value appears.

    It returns

    Each matching row once, with matched_columns. Matched columns are always included in the returned values.

    Parameters

    NameMeaning
    folder, filename, identifierrequiredAs for find_security_in_file, without a column.
    columns, max_rows, cursor, max_scan_secondsoptionalAs for find_security_in_file.
    • A row holding the value in three columns is returned once, with all three listed.
    • This is the way from a name to an identifier: search the name, read the near miss, search again with the exact value.

    Tool 8 of 9

    count_matching_rows

    Returns the exact number of rows whose chosen column equals the value, without returning any rows.

    Use it when

    You need “how many” or a firm zero, and the rows themselves would only use up the response.

    The rule

    A number is given only after a complete scan. Otherwise count is null.

    Parameters

    NameMeaning
    folder, filename, identifier, identifier_columnrequiredAs for find_security_in_file.
    cursor, max_scan_secondsoptionalContinue an interrupted count, or shorten the time budget.
    • An interrupted count reports matches_seen_before_interruption. That is a lower bound and must not be quoted as the count.
    • Near misses are reported here too, so a zero caused by the wrong column is visible.

    Level 4

    Very large files: limits, cursors, time

    The examples so far ran on small files and finished at once. On a multi-gigabyte file three things change: responses fill up, scans take time, and scans can be cut short. The server handles each one openly.

    Responses are bounded, and say when they are cut

    One response carries at most a set number of rows and a set number of bytes. When a search stops because the response is full, it says so in three places: results_are_partial is true, more_matches is "yes", and the explanation begins with “PARTIAL RESULTS”.

    The server only says "yes" when it has actually seen a further match. It reads on until it finds the next one before stopping.

    Cursors continue where a response stopped

    A partial response carries a next_cursor. Send the same call again with that cursor and the scan resumes at the exact byte where it stopped, without re-reading the start of the file. Repeat until more_matches is "none".

    Paging through matches

    Real responses. Portfolio PF001 has four rows in the custodian file and the call asks for two at a time.

    • A cursor belongs to one search on one file. Using it with a different value, column or tool is refused.
    • It is tied to the file's size and modification time. If the file changes, the cursor stops working and the search must start again.
    • Cursors do not survive a server restart.

    Scans have a time budget

    Each scan may run for a configured maximum, 120 seconds by default. A call can ask for less with max_scan_seconds. When time runs out the scan stops and returns what it has, marked incomplete, with a cursor to carry on. Every call reads at least one chunk of the file, so a chain of cursors always reaches the end.

    Progress and cancellation

    While a scan runs, the server sends MCP progress notifications to clients that ask for them. Each carries bytes scanned, the total, and a line of text such as:

    scanning: 1,204 of 2,061 MB, 2 match(es) so far, 3s of 120s allowed

    queued: waiting for a free scan slot (at most 2 scans run at once)

    Only a limited number of scans run at the same time. Others wait their turn, and waiting does not use up their time budget.

    A client can cancel a running call. The scan stops within milliseconds and its slot is freed once it has really stopped.

    Cancelled calls return nothing. The MCP protocol does not deliver a response to a request the client has cancelled. To get partial results back from a long scan, set max_scan_seconds instead. The response then arrives marked incomplete, with the matches found so far and a cursor.

    The limits, and their defaults

    All of these are set in the server's configuration file.

    SettingDefaultWhat it bounds
    max_rows_per_response25Matching rows returned by one call.
    max_output_bytes60,000The size of any tool response.
    max_cell_chars2,000Length of one returned cell before it is cut and flagged.
    max_sample_rows10Sample rows from inspect_csv_headers.
    max_files_per_listing200Files returned by one list_csv_files call.
    max_concurrent_scans2Scans running at once.
    max_scan_seconds120Time one scan may take.
    max_record_bytes4 MiBThe longest single CSV record accepted. A longer one usually means an unclosed quote.

    Level 5

    Compare one security across two files

    Most investigations end with “it was this here and that there”. The ninth tool does both lookups and the comparison in one call.

    Tool 9 of 9

    compare_security_records

    Finds a security in two files, reports whether it is present in each, and lists which fields changed and which did not.

    Use it when

    Comparing two runs of the same folder, or the files either side of a step.

    What it will not do

    Guess. If it cannot tell which record pairs with which, it says so and compares nothing.

    Parameters

    NameMeaning
    folder_a, filename_a
    folder_b, filename_b    		requiredThe two files. File A is usually the earlier or upstream one.
    identifierrequiredThe value to find in file A, and in file B unless identifier_b is given.
    identifier_column_arequiredIdentifier column in file A.
    identifier_column_boptionalIdentifier column in file B when it has a different name.
    identifier_boptionalA different value to find in file B, for when the files use different identifier types.
    compare_columnsoptionalColumns to compare, by their file A names. Leave out to compare every column the files share.
    column_mappingoptionalFile A column name to file B column name, for renamed columns. A target may be a name or #N.
    match_keysoptionalFile A columns that pair up records when a file has several for the security. Up to 10.
    max_scan_secondsoptionalOne time budget shared by both scans.

    Step 1. Two runs of the same folder

    The columns have the same names, and each file has one record for the security, so nothing more is needed.

    Step 2. Either side of a step, with renamed columns

    The custodian file calls the identifier SecurityId; the enriched file calls it sedol. column_mapping covers the other renamed columns. But two portfolios hold Halvorsen, so each file has two records.

    Step 3. Add match keys

    The response above suggested PortfolioCode. Passing it as a match key pairs the records.

    Step 4. Present on one side only

    • Values are compared as exact text. A difference that is only formatting is still listed under changed, with a note such as “numerically equal; the text formatting differs”, “equal after trimming whitespace” or “equal ignoring letter case”.
    • Columns are paired by identical name unless column_mapping says otherwise. A name that is repeated in a header is never paired automatically.
    • Without compare_columns, the response lists the columns found in only one file under columns_not_compared.
    • Each file's presence has its own outcome, with the same three values as a search.

    The comparison statuses

    comparison_statusMeaning
    comparedEvery record was paired and compared.
    partially_comparedSome pairs were compared. Others had no counterpart or an ambiguous key, and are listed.
    ambiguous_alignmentRecords could not be paired. Nothing was compared. Add or change match_keys.
    present_in_one_file_onlyComplete scans found the security in one file and not the other.
    absent_from_bothComplete scans found it in neither file.
    inconclusiveAt least one file was not fully or reliably scanned. Nothing was compared.

    Level 6

    When the file itself is the problem

    Real exports go wrong in ordinary ways. A tool that read a broken file as if it were fine would report securities as absent when they are there. CSV-o-Matic refuses to do that. It explains what is wrong and gives no verdict.

    Requests that cannot be carried out

    A mistake in the request comes back as a structured error with a suggestion, and the request echoed. For search tools the outcome is inconclusive, because no search took place.

    Files that cannot be trusted

    For these three examples, copies of the 13 November custodian file were damaged in the ways named.

    What each problem produces

    SituationWhat you get
    UTF-16 or UTF-32 text, or compressed data under a .csv nameError unsupported_encoding. Nothing can be concluded.
    A file that is not .csv, such as .csv.gzError not_a_csv_file.
    A link or special file in a mapped folderNot listed. Reading it gives file_unreadable. Links are never followed.
    Wrong delimiter declared for the folderA warning, and inconclusive in place of absent.
    Wrong encoding declared, and the value has non-ASCII charactersA warning that the value's bytes appear under another encoding, and inconclusive. Plain ASCII values are unaffected.
    Bytes that are invalid in the declared encoding, inside a returned rowThe row is returned with the replacement character, and a warning.
    An unclosed quote in a data rowMatches before it are returned as partial. A count is withheld. Hidden rows show up as a near miss.
    An unclosed quote in the header rowError parse_error for the whole file.
    One record longer than max_record_bytesError parse_error at that record. Matches found before it are returned as partial.
    No header rowThe first row is read as column names. If the value searched for is in that row, a warning is given and the result is not final.
    The file changes while it is being readA warning, inconclusive in place of absent, and no cursor.
    Two process maps declare different formats for one folderError process_map_conflict until the maps agree.
    Old-style or mixed line endingsRead correctly. A record ends at LF, CRLF or a bare CR.

    Practice

    Two investigations, from question to answer

    Each step shows what the model wanted to know, the call it made, and what the real response told it.

    Case A. The missing position

    “Portfolio PF003 holds Halvorsen Aerospace according to the custodian on 13 November 2026, but it is missing from the client holdings file for that date. Why?”

    1. Learn the route

      Which steps lie between the custodian file and the client report, and what does each one drop?

      Custodian positions go through enrich, then branch to client_report. The enrich step is an inner join on SEDOL to the golden master and drops anything unmatched. The report step only excludes portfolios starting with INT.

    2. Confirm the symptom

      Is PF003 really absent from the client file?

      Yes. A complete scan, no match in any column, and no near miss.

    3. See what the custodian sent

      What does PF003's row look like at the start of the process?

      One row: 900 units of SecurityId 417382. The quantity is not zero, so the zero-quantity rule does not apply.

    4. Find where it dropped out

      Did the position survive the enrich step?

      No. PF003 has zero rows in the enriched file. The position was lost at enrich, before the report step ever saw it.

    5. Ask why the join failed

      Is 417382 in the golden master that the 20:00 enrich run read?

      It is not there. But one value contains it: 0417382, in the same column.

    6. Identify the near miss

      Which security is 0417382?

      Halvorsen Aerospace PLC.

    Conclusion

    The custodian file carries Halvorsen's SEDOL for PF003 without its leading zero. The enrich step joins on SEDOL as text, found no match, and dropped the position. The client report is correct for the input it received. The fault is upstream, in the custodian file or whatever produced it.

    One thing is inferred, not shown: no file records which golden master a run read. The 18:30 file is assumed because the 21:15 one did not exist when enrich started at 20:00.

    Case B. Two prices for one security

    “People are quoting two different prices for Larkspur Holdings for 13 November 2026. Why are there two, and which one did the positions use?”

    1. Look for more than one run

      How many golden files exist for that business date?

      Two: one run at 18:30 and one at 21:15. The process map says the latest run supersedes the earlier one.

    2. Compare the two runs

      What differs for Larkspur between them?

      Only close_price: 452.1100 in the first run, 455.0000 in the second. Six other fields are unchanged.

    3. Trace the change upstream

      Did the build change the price, or did its input change?

      The vendor delivered twice, at 18:02 and 20:47. The first delivery has 452.11000 and the second 455.00000. The change came from the vendor.

    4. Check what the positions used

      Which price is in the enriched positions?

      452.1100. PF001 holds 40 units, valued at 18,084.40. The only enriched file ran at 20:00, before the corrected master existed.

    Conclusion

    The vendor redelivered the 13 November file at 20:47 with Larkspur's price corrected from 452.11 to 455.00. The security master was rebuilt at 21:15 and now shows 455.00. Positions were built at 20:00 from the earlier master and were not rerun, so they are valued at 452.11. Both prices are real: one is current, the other is what the published positions used.

    Rules of thumb for the model

    • Start with get_process_map. The filter rules usually name the cause before any file is opened.
    • List the files before choosing one. Two files for one business date changes the question.
    • Take identifier column names from the process map or the headers. They are exact, including case.
    • Treat inconclusive as “not yet known”. Continue with the cursor or fix the cause.
    • When a search is absent, read near_misses before moving on.
    • Say what is inferred. No file records which upstream file a run read.
